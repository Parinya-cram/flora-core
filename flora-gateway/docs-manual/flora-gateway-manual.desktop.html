1 ภาพรวมของ Flora Gateway

1.1 Gateway ทำหน้าที่อะไร

Flora Gateway คือเครื่องกลางประจำห้องผ่าตัดหรือหอผู้ป่วย ทำหน้าที่ รับข้อมูลจากเครื่องมือแพทย์ (monitor, เครื่องดมยา, เครื่องช่วยหายใจ, โมดูลวัดอุณหภูมิ ฯลฯ) ผ่าน protocol เฉพาะของแต่ละยี่ห้อ แล้ว แปลงให้เป็นรูปแบบกลางของ Flora (เช่น hr = 76 /min) จากนั้นเก็บไว้และให้ Flora Leaf (เครื่องประจำเตียง) ดึงไปแสดงผลผ่าน data-api

  • เครื่องมือแพทย์ต่อได้หลายแบบ: RS-232 (สาย serial), TCP/UDP (LAN), HTTP (push / poll), HL7 v2
  • หนึ่ง gateway รองรับเครื่องหลายตัว และส่งข้อมูลแยกตาม Leaf ที่เป็นเจ้าของเครื่องนั้น
  • การตั้งค่าอุปกรณ์, ไลเซนส์, และการอัปเดต ถูกควบคุมจากส่วนกลางผ่าน Canopy / Haber

1.2 การไหลของข้อมูล

  1. Controller เปิดพอร์ตหรือ connection แล้วส่ง bytes ดิบเข้า Kafka topic gw.raw.<pod>
  2. Parser ของ device นั้นอ่านข้อมูลดิบ ตรวจ checksum/โครงสร้าง แปลงเป็น observation แล้วส่งไป gw.obs ถ้าเครื่องต้องถามก่อนตอบ (poll) หรือต้องตอบ ACK parser จะส่งคำสั่งกลับทาง gw.cmd.<pod>
  3. Collector บันทึกลงฐานข้อมูล, server ให้ API อ่านค่า, kong เปิด data-api ที่พอร์ต 7410 แยกตาม Leaf
  4. Leaf ดึงค่าจาก http://<gateway>:7410/data-api/<leaf-id>/api/observations

3 การติดตั้งทีละขั้นตอน

3.1 เตรียม Ubuntu

อัปเดตระบบและติดตั้งเครื่องมือพื้นฐาน 
sudo apt update && sudo apt -y upgrade
sudo apt -y install git curl python3 python3-serial
ให้ผู้ใช้เข้าถึงพอร์ต serial ได้ (กลุ่ม dialout) แล้ว logout/login ใหม่ 1 ครั้ง 
sudo usermod -aG dialout $USER
ตรวจว่าเครื่องเห็นพอร์ต serial จริง (บรรทัดที่ uart ไม่ใช่ unknown คือพอร์ตที่มีอยู่จริง) 
ls -l /dev/ttyS* /dev/ttyUSB* 2>/dev/null
sudo cat /proc/tty/driver/serial | head -4   # 0: uart:16550A ... = COM1 จริง
ปิดโปรแกรมที่อาจแย่งพอร์ต serial (ModemManager ชอบไปเปิดพอร์ตเพื่อหาโมเด็ม) 
sudo systemctl disable --now ModemManager

3.2 ติดตั้งและตั้งค่า Docker Desktop

ดาวน์โหลดแพ็กเกจ .deb ของ Docker Desktop for Linux จากเว็บไซต์ Docker แล้วติดตั้ง 
sudo apt -y install ./docker-desktop-amd64.deb
เปิด Docker Desktop และยอมรับเงื่อนไข จากนั้นตั้งค่า Settings → Resources → Advanced
ค่าแนะนำเหตุผล
CPU limit3เหลือ 1 core ให้ Ubuntu ไม่ให้เครื่องค้าง
Memory limit4 GBค่าเริ่มต้น ~2 GB ไม่พอ: Kafka start ช้า, healthcheck timeout (ดูบทที่ 11)
Swap1 GB
แล้วกด Apply & restart
เปิด Settings → General → Start Docker Desktop when you sign in หรือใช้คำสั่ง 
systemctl --user enable docker-desktop
ตรวจว่า CLI ใช้ context ของ Docker Desktop 
docker context use desktop-linux
docker info --format 'CPUs={{.NCPU}} RAM={{.MemTotal}}'
ข้อจำกัดของ Docker Desktop บน Linux Docker Desktop รัน container ใน VM จึง map พอร์ต serial ของเครื่อง (/dev/ttyS0) เข้า container โดยตรงไม่ได้ (ใน VM นั้น /dev/ttyS0 คือ console ของ VM) ต้องใช้ bridge ของ COM1 ตามหัวข้อ 7.2 และ Docker Desktop จะเริ่มทำงานหลัง login เท่านั้น จึงต้องตั้ง auto-login (บทที่ 4)

3.3 ดึงซอร์สโค้ด

mkdir -p ~/flora && cd ~/flora
git clone http://172.22.1.103:8080/esm-solution/flora-esm flora-core
cd flora-core/flora-gateway
ห้ามย้ายหรือเปลี่ยนชื่อโฟลเดอร์หลังติดตั้ง container จำ path ของไฟล์ที่ mount ไว้ ถ้าย้ายโฟลเดอร์ (เช่น เคยเปลี่ยน frola → flora) Docker จะสร้างโฟลเดอร์เปล่าแทนไฟล์เดิม ทำให้ฐานข้อมูล start ไม่ได้และเว็บเปิดไม่ได้ ถ้าจำเป็นต้องย้าย ให้รัน docker compose -p flora-gateway up -d --force-recreate จากตำแหน่งใหม่ทันที

3.4 ไฟล์ตั้งค่า .env

สร้างไฟล์ flora-gateway/.env (ไม่ถูก commit เข้า git) ค่านี้เป็นค่าเฉพาะของเครื่อง:

# Gateway host 172.22.1.233 — Canopy/Haber อยู่ที่ 172.22.1.151
HABER_URL=http://172.22.1.151:7204
GATEWAY_DATA_API_URL=http://172.22.1.233:7410/data-api
FLORA_GATEWAY_DATA_API_PORT=7410
FLORA_GATEWAY_ADMIN_BIND=0.0.0.0
FLORA_CANOPY_IP=172.22.1.151
FLORA_GATEWAY_CONFIG_FILE=gateway.site.toml
FLORA_GATEWAY_SEED_FILE=instances.site.json
# ตั้งเพิ่มตามที่ Canopy ให้มา (ไม่ใส่ = ใช้ค่า demo)
# FLORA_GATEWAY_ID=gateway-hospital-01-a
# HABER_GATEWAY_TOKEN=...
# HABER_NODE_TOKEN=...
# GATEWAY_ADMIN_PASSWORD=...   (รหัส admin เริ่มต้น)
ตัวแปรความหมาย
HABER_URLที่อยู่ Haber ที่ gateway และ updater ใช้ check-in / ขออัปเดต
GATEWAY_DATA_API_URLที่อยู่ data-api ที่ Leaf จะเห็น (แสดงใน wizard ของ Leaf)
FLORA_GATEWAY_DATA_API_PORTพอร์ต data-api บนเครื่อง (ค่าเริ่มต้น 7410)
FLORA_GATEWAY_ADMIN_BIND0.0.0.0 = เปิดหน้า admin ให้เครื่องอื่นใน LAN, ไม่ตั้ง = เฉพาะเครื่องนี้
FLORA_CANOPY_IPIP ที่ชื่อ canopy.flora.local ชี้ไป (ใช้เมื่อเชื่อม Canopy แบบ HTTPS ด้วย cert ของ *.flora.local)
FLORA_GATEWAY_CONFIG_FILEไฟล์ pod ของไซต์ใน config/
FLORA_GATEWAY_SEED_FILEไฟล์ device เริ่มต้น; ใช้ไฟล์ว่าง [] เพื่อไม่ให้ device ตัวอย่างถูกเพิ่มเอง

3.5 ไฟล์ตั้งค่า pod ของไซต์

คัดลอกไฟล์ตัวอย่างเป็นไฟล์ของไซต์ แล้วแก้เฉพาะ pod ที่ใช้จริง:

cp config/gateway.toml config/gateway.site.toml
echo '[]' > config/instances.site.json

ตัวอย่าง pod ที่ใช้งานในเครื่องอ้างอิง (ส่วนที่สำคัญ):

[serial]
admin_port = 5001

[[serial.pods]]
id = "COM1"
# COM1 จริงเข้ามาทาง bridge (host /dev/ttyS0 <-> 127.0.0.1:7430)
path = "/dev/ttyV0"
baud = 19200
idle_ms = 20
max_frame_bytes = 16384

[socket]
admin_port = 5004

[[socket.pods]]
id = "or-monitor"           # HL7 (MLLP) — พอร์ตบนเครื่อง 7421
port = 9001
framing = "mllp"
auto_ack = true

[[socket.pods]]
id = "icu-monitor"          # Dräger Vista 120 S (raw) — พอร์ตบนเครื่อง 7422
port = 9002
framing = "raw"
auto_ack = false

ตรวจไฟล์ก่อนใช้งานทุกครั้ง (ไม่แตะฮาร์ดแวร์):

python3 scripts/validate_config.py config/gateway.site.toml config/instances.site.json
# Valid configuration: 8 pods, 0 device instances. No hardware was contacted.

3.6 Build และเริ่มระบบ

cd ~/flora/flora-core/flora-gateway
docker compose -p flora-gateway build          # ครั้งแรกใช้เวลา ~10–15 นาที (Rust)
docker compose -p flora-gateway up -d
ต้องใช้ -p flora-gateway เสมอ ชื่อ project ถูกใช้ตั้งชื่อ network (flora-gateway_default) ที่ gateway-service ใช้สร้าง parser container ถ้าใช้ชื่ออื่น parser จะต่อ Kafka ไม่ได้

docker compose -p flora-gateway ps                       # ทุกตัว Up, db/kafka/kong/server = healthy
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7400/health    # 200
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7410/data-api/leaf-or-01/health   # 200

จากนั้นเปิด http://172.22.1.233:7400 จากเครื่องอื่นใน LAN เข้าสู่ระบบ และ เปลี่ยนรหัส admin ทันที

4 ให้ระบบเริ่มเองอัตโนมัติเมื่อเปิดเครื่อง

เป้าหมาย: เปิดเครื่องแล้วไม่ต้องกดอะไร ระบบทำงานครบเอง ลำดับที่เกิดขึ้นคือ

  1. Ubuntu login ผู้ใช้ esm ให้เอง (auto-login)
  2. Docker Desktop เริ่ม → container ทั้งหมด (restart: unless-stopped) เริ่มตาม
  3. service flora-com1-bridge เริ่ม และรอจน serial-controller พร้อม
  4. service flora-watch เริ่ม และบันทึกว่าเครื่องปิดไปนานเท่าไร

4.1 เปิด auto-login

sudo sed -i 's/^#  AutomaticLoginEnable = true/AutomaticLoginEnable = true/; s/^#  AutomaticLogin = user1/AutomaticLogin = esm/' /etc/gdm3/custom.conf
grep -E "^AutomaticLogin" /etc/gdm3/custom.conf      # ต้องเห็น true และ esm
ความปลอดภัยauto-login ทำให้ผู้ที่อยู่หน้าเครื่องใช้งานได้ทันที ให้ตั้ง Screen Lock อัตโนมัติ (Settings → Privacy → Screen Lock) การล็อกหน้าจอไม่ทำให้ Docker หยุด

4.2 service ของผู้ใช้

systemctl --user enable docker-desktop flora-com1-bridge flora-watch
systemctl --user is-enabled docker-desktop flora-com1-bridge flora-watch   # enabled x3

ไฟล์ unit อยู่ที่ ~/.config/systemd/user/ (รายละเอียดของ bridge ดูหัวข้อ 7.2, flora-watch ดูหัวข้อ 10.2)

4.3 ทดสอบ

รีบูตเครื่อง 1 ครั้ง ไม่ต้องแตะเครื่อง รอ 1–2 นาที แล้วเปิด http://172.22.1.233:7400 จากเครื่องอื่น และดู log

python3 ~/flora/flora-core/flora-gateway/scripts/flora_watch.py --summary 1
ทางเลือก: ไม่ต้อง login เลยถ้าต้องการให้ทำงานโดยไม่ต้องมี session ผู้ใช้ ให้ใช้ Docker Engine (systemd ของเครื่อง) แทน Docker Desktop ข้อดี: เริ่มตั้งแต่ boot, map /dev/ttyS0 เข้า container ได้ตรง (ไม่ต้องใช้ bridge), ใช้ CPU/RAM น้อยกว่า ข้อเสีย: ไม่เห็น container ในหน้าต่าง Docker Desktop (ใช้ Portainer แทน)

5 การเชื่อมต่อ Canopy และไลเซนส์

5.1 ลิงก์ไปยัง Canopy / Haber

gateway check-in ไปที่ Haber ทุก ~20 วินาที เพื่อรายงานสถานะ, รับไลเซนส์, รับ catalog ของประเภทเครื่อง และรับการตั้งค่าที่ Canopy สั่ง ค่าที่บันทึกในหน้า admin (ส่วน Canopy link) จะใช้แทนค่าใน .env

รูปแบบที่อยู่ใช้เมื่อ
http://172.22.1.151:7204เชื่อม Haber ตรง (แนะนำ ใช้ได้ทันที)
https://canopy.flora.local:9443ผ่าน edge ของ Canopy แบบ HTTPS — ต้องติดตั้ง cert ของ Canopy (5.2) และ edge ต้องส่ง /api/haber/ ไปที่ Haber

5.2 ติดตั้ง cert ของ Canopy (กรณี HTTPS ใช้ self-signed)

echo | openssl s_client -connect 172.22.1.151:9443 -showcerts 2>/dev/null \
  | awk '/BEGIN CERT/,/END CERT/' > certs/canopy-trust.pem
echo "SSL_CERT_FILE=/etc/flora/certs/canopy-trust.pem" > certs/trust.env

ทำไมต้องใช้ชื่อ canopy.flora.localcert ของ Canopy ออกให้ *.flora.local ไม่ได้ออกให้ IP จึงต้องเรียกด้วยชื่อ ซึ่ง compose ชี้ชื่อนี้ไปที่ FLORA_CANOPY_IP ให้แล้ว

5.3 ไลเซนส์

ไลเซนส์ออกโดย Flora Root ส่งผ่าน Canopy มายัง gateway กำหนด จำนวน device สูงสุด และ ประเภท device ที่อนุญาต (allowed_types) การเพิ่ม device ประเภทที่ไม่อยู่ในไลเซนส์จะได้ข้อความ device type ... is not licensed

เพิ่มประเภทเครื่องในไลเซนส์ (ทำที่ Root — ต้องระบุค่าเดิมทั้งหมดด้วย เพราะเป็นการออกไลเซนส์ใหม่ทั้งชุด):

curl -sk -u <root-admin>:<password> -H 'content-type: application/json' -X PUT \
  https://172.22.1.151:8443/api/v1/tenants/hospital-01/license \
  --data '{"modules":["leaf","canopy","gateway"],"max_leaves":4,"max_gateways":2,
  "max_gateway_devices":8,"device_types":["hl7-patient-monitor","json-anesthesia-machine",
  "http-ventilator","serial-temp-module","draeger-medibus","draeger-vista-120s",
  "draeger-iacs-m540"],"valid_days":365}'

ภายใน ~1 นาที gateway จะได้ไลเซนส์ใหม่ ตรวจได้ที่หน้า admin หรือ

curl -s -u admin:<password> http://127.0.0.1:7400/api/license
ก่อนแก้ไลเซนส์อ่านค่าปัจจุบันจาก Root ก่อนเสมอ (GET /api/v1/overview) แล้วคงค่าเดิมไว้ เพิ่มเฉพาะที่ต้องการ และตรวจว่า Canopy ของไซต์ใช้ Root ตัวไหน (ดูจาก bundle_id ที่ gateway ได้รับ)

6.4 หน้า Monitor ของ pod

การ์ด pod (เช่น serial.COM1) แสดง

  • รายชื่อ device = device ที่ ตั้งค่า ให้ใช้ pod นี้ (รวมตัวที่ปิดอยู่) ไม่ได้แปลว่าตรวจพบเครื่อง — RS-232 ไม่มีสัญญาณบอกว่ามีสายเสียบ
  • เส้นสีส้ม (out) = คำสั่งที่ gateway ส่งไปเครื่อง เช่น poll, handshake — ส่งออกเสมอแม้ไม่มีเครื่อง
  • เส้นสีน้ำเงิน (in) = ข้อมูลที่เครื่องส่งกลับ — ถ้าแบนที่ 0 แปลว่าไม่มีเครื่องตอบ
  • ตาราง Payloads แสดงข้อมูลดิบแต่ละ frame (เลือกดูแบบ text/hex, in/out ได้)
วิธีบอกว่าเครื่องต่ออยู่จริงมี frame in เข้ามา และ device ขึ้น online ใน Installed devices / data-api

6.5 Alerts

  • device ที่ เปิดอยู่ แต่ไม่มีข้อมูล 2 รอบติด (~1 นาที) → alert Critical: No data from … และส่งไป Canopy
  • Acknowledge = บันทึกว่ารับทราบ alert ยังไม่ปิด; alert ปิดเองเมื่อมีข้อมูลเข้า หรือ device ถูกปิด/ลบ
  • controller ล่ม → Controller down; ต่อ Canopy ไม่ได้ → Canopy connection lost

7 การเพิ่มอุปกรณ์แต่ละประเภท

7.1 แนวคิด pod / device / parser

คำความหมายกำหนดที่
Podช่องทางเชื่อมต่อหนึ่งช่อง: พอร์ต serial หนึ่งพอร์ต หรือพอร์ต TCP หนึ่งพอร์ต พร้อมรูปแบบการตัด frameconfig/gateway.site.toml (แก้แล้วต้อง restart controller)
Deviceเครื่องมือแพทย์หนึ่งเครื่อง ผูกกับ pod หนึ่งตัวและ Leaf หนึ่งตัวหน้า admin → Installed devices
Parserโปรแกรมแปลง protocol ของเครื่อง 1 container ต่อ 1 deviceเลือกผ่าน device type
กฎสำคัญ
  • พอร์ตจริง 1 พอร์ต เปิดได้โดย pod เดียว
  • เครื่องแบบ poll (MEDIBUS, temp module) ห้ามมี device ที่เปิดอยู่มากกว่า 1 ตัวบน pod เดียวกัน — poll จะชนกันและค่าถูกบันทึกซ้ำ
  • framing ของ pod ต้องตรงกับ protocol: HL7 = mllp, binary (Vista) = raw

7.2 RS-232 (COM1) และ bridge

เพราะ Docker Desktop map /dev/ttyS0 ไม่ได้ ระบบจึงใช้ bridge บนเครื่อง ต่อ COM1 จริงเข้ากับพอร์ตเสมือน /dev/ttyV0 ของ serial-controller ผ่าน TCP 127.0.0.1:7430

เครื่องมือแพทย์ ── สาย RS-232 ── COM1 (/dev/ttyS0) ── serial_tcp_bridge.py ── 127.0.0.1:7430 ── ttyV0 ── pod serial.COM1

ไฟล์ ~/.config/systemd/user/flora-com1-bridge.service:

[Unit]
Description=Flora gateway: physical COM1 (/dev/ttyS0) <-> serial-controller ttyV0 (127.0.0.1:7430)
After=docker-desktop.service
Wants=docker-desktop.service

[Service]
# ค่าสายของ MEDIBUS.X; ถ้าใช้ temp module ให้ใช้ --baud 9600 และเอา --parity/--rts/--dtr ออก
ExecStart=/usr/bin/python3 /home/esm/flora/flora-core/flora-gateway/scripts/serial_tcp_bridge.py \
  --serial /dev/ttyS0 --tcp 127.0.0.1:7430 --baud 19200 --parity even --rts --dtr
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
ค่าความเร็ว/parity กำหนดที่ bridgeเมื่อใช้ bridge ค่า baud/parity ของ pod ใน toml ไม่มีผลกับพอร์ตจริง ให้แก้ที่บรรทัด ExecStart แล้วรัน systemctl --user daemon-reload && systemctl --user restart flora-com1-bridge
journalctl --user -u flora-com1-bridge -n 5     # ดูสถานะ / จำนวน bytes เข้าออกทุก 60 วินาที

9.1 ตัวจำลอง RS-232

  • รันบน อีกเครื่องหนึ่ง แล้วต่อสาย null-modem เข้า COM1 ของ gateway (บน gateway เองใช้ไม่ได้เพราะ COM1 ถูก bridge ใช้อยู่)
  • ค่าสายต้องตรงกับ bridge (MEDIBUS 19200 8E1 / temp 9600 8N1)
  • หน้าจอตัวจำลองต้องเห็น RX ICC (MEDIBUS) หรือ RX '?' (temp) ทุกรอบ poll; ถ้าเห็นแต่ "nothing yet (check cable/port)" = สาย/พอร์ตไม่ถูก
  • ตัวเลือก: --list แสดงพอร์ต, --fixed ค่าคงที่, --print แสดง frame โดยไม่เปิดพอร์ต

9.2 ตัวจำลอง Vista 120 S

  • ต่อ TCP เข้า gateway ได้รับ greeting แล้วส่ง vitals ทุก 1 วินาที, NIBP เปลี่ยนทุก 60 วินาที
  • ตัวเลือก: --noise (ปน message ชนิดอื่น), --no-spo2, --no-temp, --no-nibp (จำลองถอด sensor)
  • หลุดการเชื่อมต่อจะต่อใหม่เองทุก 3 วินาที
10:19:51 connected; greeting 100002000000d5a9d907080e113b2605 (16 bytes, matches the CMS greeting)
10:19:51 TX   78 B  HR=76 RR=14 NIBPs=132 NIBPd=76 NIBPm=95 SpO2=98 PR=76 T1=36.8

ดึงโค้ดใหม่ แล้วตรวจว่า .env, config/gateway.site.toml, config/instances.site.json ยังอยู่ 
cd ~/flora/flora-core && git pull
cd flora-gateway && git status --short
ตรวจ config และ build (ระบบเดิมยังทำงานระหว่าง build) 
python3 scripts/validate_config.py config/gateway.site.toml config/instances.site.json
docker compose -p flora-gateway build
เริ่มด้วย image ใหม่ และ ลบ parser container เก่า ให้ gateway-service สร้างใหม่จาก image ใหม่ 
docker compose -p flora-gateway up -d
docker rm -f $(docker ps -aq --filter name=flora-gw-parser)
ตรวจตามหัวข้อ 3.7 และดู flora_watch.py --summary 1
ทำไมต้องลบ parser เก่าparser container อ้าง image ID เดิม เมื่อ build parser ใหม่ image เดิมถูกแทนที่ gateway-service จะ check-in ไม่ได้ (404 ... No such image) จนกว่าจะสร้าง parser ใหม่

10.5 Portainer (ทางเลือก)

หน้าเว็บจัดการ Docker เปิดที่ https://localhost:9443 ใช้ดู log/สถานะ/restart ได้ ไม่ควรแก้ค่าหรือลบ container ของ gateway ใน Portainer เพราะ compose/updater จะเขียนทับ หมายเหตุ: Portainer ที่รันบน Docker Engine จะไม่เห็น container ของ Docker Desktop (คนละ engine)
