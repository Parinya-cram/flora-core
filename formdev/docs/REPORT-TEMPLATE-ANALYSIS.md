# วิเคราะห์: เปลี่ยน Report บน Flora Leaf ไปใช้ Template ของ Form Studio

สถานะ: **บทวิเคราะห์ ยังไม่ได้พัฒนา** · 2026-10-14 · ตัวอย่างอ้างอิง: `เอกสาร 16.pdf`
(KCMH Anesthetic Record ฟอร์ม น. 6002, A4 แนวตั้ง 1 หน้า)

## 1. การพิมพ์ Report บน Leaf ในปัจจุบัน

| | Electron (แอปเดสก์ท็อป) | เบราว์เซอร์ทั่วไป |
|---|---|---|
| ตัวสร้าง | `electron/reportPdf.cjs` (1,675 บรรทัด, pdf-lib) ไม่มี test | หน้า HTML/Tailwind ใน `ReportView.tsx` แล้วสั่ง `window.print()` |
| ฟอนต์ | Tahoma / Leelawadee จาก `C:\Windows\Fonts` เท่านั้น ถ้าไม่ใช่ Windows จะเหลือ Helvetica ซึ่งไม่มีอักษรไทย | ฟอนต์ของเบราว์เซอร์ |
| รูปแบบ | หน้า 1: สรุป (รายการถูกตัดตามจำนวนที่ตั้งไว้), หน้า 2..N: timeline | คล้ายกัน แต่ความกว้างคอลัมน์ เหตุการณ์ และตารางเลือดไม่เหมือนฉบับ PDF |
| ปรับแต่งได้ | ไม่ได้: หัวกระดาษ โลโก้ และลำดับส่วน hardcode ตาม edition | ไม่ได้ |
| ลายเซ็น / remarks | ไม่มี | ไม่มี |

โหมด standard / smart_fit / detail คำนวณใน `ReportView.tsx` (ไม่ได้อยู่ใน PDF):
- **standard:** คอลัมน์ละ 15 นาที หน้าละ 4 ชั่วโมง
- **detail:** คอลัมน์ละ 5 นาที
- **smart_fit:** เลือกขนาดคอลัมน์ 5/10/15/20/30/60 นาที ให้ได้หน้าละ 16 คอลัมน์ ครอบคลุมไม่เกินประมาณ 5.5 ชั่วโมงต่อหน้า

**เทคนิคบีบเนื้อหาที่ใช้อยู่:**
- ปรับสเกลเวลาแทนการย่อหน้ากระดาษ
- รวมค่าต่อช่วงเวลา (ช่องตารางใช้ค่าแรก, กราฟใช้ค่าสุดท้าย)
- ย่อรหัส (ECG, event 2 ตัวอักษร)
- จำกัด badge ต่อช่อง
- ซ่อนแถวที่ไม่มีข้อมูลในหน้านั้น
- ความสูงแถวยืดหยุ่น 12–15pt และฟอนต์ 6.2–6.8pt
- จำกัดไม่เกิน 43 แถว
- รายการหน้า 1 ถูกตัด (เช่น diagnosis 6, ยา 8) และ event แสดง "+N more"

**ข้อจำกัดสำคัญ:** เนื้อหาที่ไม่พอดีหน้าจะถูก **ตัดทิ้งหรือล้นออกนอกหน้ากระดาษ** ไม่ไหลไปหน้าถัดไป ซึ่งไม่เหมาะกับเอกสารทางการแพทย์

**บั๊กที่พบระหว่างวิเคราะห์:** ปุ่ม "Open / Print" ส่งข้อมูลชุดที่ยังไม่ตัดแถว (`reportPdfModel`, `ReportView.tsx:815`) ส่วนหน้าพรีวิวใช้ชุดที่ตัดแล้ว ไฟล์ที่พิมพ์ออกมาจึงอาจไม่ตรงกับที่เห็นในพรีวิว

## 2. Form Studio ทำแทนได้หรือไม่

**ทำได้ และควรทำ** แต่ต้องเพิ่มความสามารถ "บีบเนื้อหา" ก่อน

| สิ่งที่ Form Studio มีแล้ว | สิ่งที่ยังขาด (เทียบกับ Report เดิมและกระดาษตัวอย่าง) |
|---|---|
| PDF ในเบราว์เซอร์ใดก็ได้ ไม่ต้องใช้ Electron | ขนาดตายตัว: label 7.5pt, ค่า 9.5pt, timeline คอลัมน์ละ 9.6 มม. (ราว 13–15 คอลัมน์ต่อหน้า) |
| ฝังฟอนต์ไทยเอง (fontkit) ทุกระบบปฏิบัติการ | ไม่มีการเลือกสเกลเวลาอัตโนมัติ (smart fit) |
| กล่องแบบกระดาษ, ตาราง 24 คอลัมน์, matrix, repeat แบบตาราง | ความสูงแถว 5 มม. ตายตัว ไม่ยืดหดตามพื้นที่ |
| หัวและท้ายกระดาษซ้ำทุกหน้า, ลายเซ็น | ไม่ซ่อนแถวว่าง, ไม่มี badge เหตุการณ์ในช่อง, ไม่มีแท่งยาหยด (drip bar) |
| เนื้อหาไหลข้ามหน้าได้โดยไม่ตัดทิ้ง | ไม่มีโหมด "ให้พอดี 1 หน้า" (fit to page) |
| แก้หน้าตาได้เองใน Designer และ preview A4 ตรงกับที่พิมพ์ | ช่องยังดึงข้อมูลจาก Leaf ไม่ได้ (ต้องมี `bind`) ยกเว้น timeline |

## 3. บีบเนื้อหาได้มากแค่ไหน (A4 แนวตั้ง ขอบ 8 มม. = พื้นที่ใช้งาน 194 × 281 มม.)

| ค่า | Form Studio ตอนนี้ | หลังเพิ่มโหมดกะทัดรัด | กระดาษตัวอย่าง |
|---|---|---|---|
| คอลัมน์เวลาต่อหน้า | 13–15 | 24 (คอลัมน์ละ ~6.9 มม.) สูงสุด 32 (~5.2 มม., ใช้รหัสย่อ) | ~24 ช่องใหญ่ |
| ช่วงเวลาต่อหน้า | 15 คอลัมน์ × step | 24 คอลัมน์ × 5–30 นาที = 2–12 ชม. | ประมาณ 4–6 ชม. |
| ความสูงแถวตาราง | 5 มม. | 3.5 มม. (ต่ำสุด 3.2) | ~3.5 มม. |
| แถวในพื้นที่ 90 มม. | 18 | ~25 | ~17 |
| ขนาดตัวอักษร | 7.5–9.5pt | 6–6.5pt (ต่ำสุด 5.5pt) | ~6–7pt |
| กราฟ BP/ชีพจร | 58 มม. | 50–75 มม. (ยืดตามพื้นที่ที่เหลือ) | ~70 มม. |

**ขีดจำกัดที่ไม่ควรเกิน:**
- **ตัวอักษรต่ำกว่า 5.5pt:** อ่านยากเมื่อพิมพ์หรือสแกน
- **แถวต่ำกว่า 3.2 มม.:** เขียนด้วยมือเพิ่มไม่ได้
- **คอลัมน์แคบกว่า 5 มม.:** ใส่ตัวเลข 3 หลักไม่พอ

เกินจากนี้ให้ใช้หน้าต่อ (continuation) แทนการบีบต่อ

## 4. รูปแบบที่แนะนำ: "1 หน้าหลักแบบกระดาษเดิม + หน้าต่ออัตโนมัติ ไม่ตัดข้อมูลทิ้ง"

แบ่งหน้าหลักเป็น 6 โซน รวมประมาณ 269 มม. จาก 281 มม.:

| โซน | ความสูง | เนื้อหา | ที่มาของข้อมูล |
|---|---|---|---|
| A หัวผู้ป่วย | 42 มม. | 3 คอลัมน์แบบกระดาษ: วันที่, ชื่อ, อายุ, น้ำหนัก, ส่วนสูง, ASA, consent, lab, CXR, ECG, allergy, HN/ward, premed, diagnosis, operation | `bind` จากเคส / HIS / บันทึกในตัว |
| B ยาดม ยา สารน้ำ | 60 มม. | ตารางเวลา ~16 แถว, แท่งยาหยด, ยาที่ฉีดครั้งเดียว | Leaf timeline + I/O |
| C เฝ้าระวัง | 32 มม. | เสียเลือด, ปัสสาวะ, EKG, CVP, SpO2, EtCO2, Paw, อุณหภูมิ | Leaf timeline |
| D กราฟ | 70 มม. | BP ▼▲, ชีพจร •, สัญลักษณ์เริ่ม/จบยาและผ่าตัด, สเกล 20–240 | Leaf vitals + events |
| E สรุปท้าย | 55 มม. | ยารวม/ขนาด, สารน้ำรวม, เลือด, เทคนิค, ท่า, airway (✓), เครื่องเฝ้าระวัง (✓), remarks | `bind` + I/O summary |
| F ลายเซ็น | 10 มม. | วิสัญญีแพทย์, พยาบาลส่งเครื่องมือ, ศัลยแพทย์ | staff |

**กติกาการบีบ (เรียงตามลำดับที่ระบบลองทำ):**
1. **เลือกสเกลเวลา (smart fit):** ให้ทั้งเคสอยู่ใน 24 คอลัมน์ โดยเลือก 5/10/15/20/30 นาที
2. **ซ่อนแถวว่าง** (แถวที่ template บังคับแสดงยังอยู่)
3. **ลดความสูงแถวและตัวอักษร** ไม่ต่ำกว่าขีดจำกัดในหัวข้อ 3
4. **รายการยาว** (diagnosis, ยา, event) แสดงเท่าที่พอดีพร้อม "ดูต่อหน้า 2 (+N)" **ห้ามตัดทิ้งเงียบ ๆ**
5. **เคสยาวเกิน 30 นาที × 24 คอลัมน์ (12 ชม.):** ขึ้นหน้าต่อ ซึ่งมีหัวผู้ป่วยแบบย่อ + โซน B–D ช่วงเวลาถัดไป แบบเดียวกับใบต่อของกระดาษ
6. **หน้าภาคผนวก (ถ้ามี):** รายการที่เกิน (event ทั้งหมด, ยาทั้งหมด, lab) แบบเต็ม ไม่ตัด

**สิ่งที่ผู้ใช้กำหนดได้ใน Form Studio ต่อฟอร์ม:**
- โหมดพิมพ์: `normal` / `compact` / `fit_one_page`
- ขีดจำกัดต่ำสุดของตัวอักษร
- จำนวนคอลัมน์เวลาเป้าหมาย
- แถวที่ต้องแสดงเสมอ
- ลำดับความสำคัญของแถวเมื่อพื้นที่ไม่พอ

## 5. แผนเปลี่ยนผ่าน

1. **เพิ่มโหมดบีบเนื้อหาใน Form Studio PDF engine** (`pdfLayout.ts`):
   - โหมดพิมพ์ต่อฟอร์ม/ส่วน, ขนาดตัวอักษรและความสูงแถวยืดหดได้, fit-to-page
   - timeline: smart fit, จำนวนคอลัมน์เป้าหมาย, ซ่อนแถวว่าง, badge เหตุการณ์, drip bar, สัญลักษณ์แบบกระดาษ
   - รายการยาวแสดง "+N" พร้อมหน้าภาคผนวก
   - ทุกข้อต้องมี test
2. **`bind` ช่องหลัก ~20 รายการ:** ดึงข้อมูลเคส / HIS / บันทึกในตัว ตอนพิมพ์ (ตาม INTEGRATION-ANALYSIS.md)
3. **สร้าง Template "Anesthetic Record (1 หน้า)"** แบบ KCMH น. 6002 ใน Form Studio และเก็บเข้าคลังแม่แบบ
4. **หน้า Reports บน Leaf:** เพิ่มตัวเลือก "Template ของ Form Studio" ข้างตัวเดิม ใช้คู่กันเพื่อเทียบผลจริงกับเคสหลายแบบ (สั้น, ยาว, ยาเยอะ)
5. **เมื่อผลเทียบเท่าแล้ว:** ตั้งเป็นค่าเริ่มต้นตาม workflow / edition แล้วค่อยปลด `reportPdf.cjs`
   - ตัว Electron ใช้แค่เปิด/สั่งพิมพ์ PDF ที่ได้
   - เบราว์เซอร์ทั่วไปได้ PDF แบบเดียวกัน ไม่ต้องใช้หน้า HTML แยก
