# Form Studio รุ่นที่ 2: ประกอบร่างเอกสาร อ่านเอกสารด้วยเครื่องมือ และตัวออกแบบแบบ 2 มิติ

เอกสารนี้อธิบายสิ่งที่เปลี่ยนใน Form Studio (Canopy → สร้างฟอร์ม) และเหตุผล

หลักการที่ใช้ตลอด: **เครื่องมือหาหลักฐาน AI แค่ตีความ และทุกคำตอบของ AI ต้องตรวจกับหลักฐานได้** (แนวทางเดียวกับระบบ IDP)
- งานที่เครื่องมือแบบกำหนดแน่นอน (deterministic) ทำได้ ให้เครื่องมือทำ ได้แก่ อ่านชั้นข้อความใน PDF, OCR, หาเส้นกรอบ เซลล์ ที่เขียน ตารางกราฟ ช่องติ๊ก และตั้งชื่อตัวแปร
- เมื่อเปิด AI ระบบส่ง **หลักฐานครบทุกบรรทัด** ให้ (ไม่ใช่แค่ภาพตัดบางจุด) และ AI ตอบเป็น "รายการแก้" ที่ต้องชี้กลับไปที่หลักฐานบนหน้า สิ่งที่ไม่ตรงกับเอกสารจะถูกปฏิเสธและแสดงเหตุผลให้เห็น
- ทุกบรรทัดของเอกสารต้องถูกใช้ในช่องใดช่องหนึ่ง หรือถูกตัดออกพร้อมเหตุผล (ความครบถ้วน หรือ coverage) จึงเห็นได้ทันทีว่ามีอะไรตกหล่น
- ไฟล์ถูกส่งเป็นไบต์จริงครั้งเดียว (ไม่ใช้ Base64) แล้วใช้ซ้ำด้วยรหัสไฟล์ (§8)

## 1. แท็บที่จัดใหม่ (ไม่ซ้ำกัน)

| แท็บ | ใช้ทำอะไร |
|---|---|
| ข้อมูลที่บันทึก | ดูและค้นหาข้อมูลที่กรอกแล้ว |
| ออกแบบฟอร์ม | ตัวออกแบบแบบลากวาง (§4) มีแถบเครื่องมือ ✨ AI และ 🔤 ตรวจชื่อตัวแปร พร้อมค้นหาส่วนประกอบด้วย Ctrl+K (§7) |
| เอกสาร | ประกอบร่างเอกสาร (§6) และอ่านเอกสารเป็นฟอร์ม (§5) |
| คลังแม่แบบ | แม่แบบ ชุดช่องของทีม และฟอร์มที่สร้างจาก AI ซึ่งรอตรวจ |
| คิวรี / งานเบื้องหลัง | เหมือนเดิม |

สิ่งที่ตัดออกเพราะทำงานซ้ำกัน:
- **แท็บ "ตัวอย่าง" (preview)** ตัวออกแบบดูตัวอย่างได้อยู่แล้ว ทั้งบนจอ (🖥 ▭ 📱) และบน PDF
- **ปุ่ม "เพิ่มส่วน" ปุ่มที่สอง**
- **แผง "Design" เดิม** ส่วนแพ็กเกจฟอร์มยังอยู่ แต่ย้ายไปอยู่ใน PackagePanel

## 2. จุดเรียกใช้ AI (มีแค่ 3 จุด และบอกชัดว่า AI จะเห็นอะไร)

1. **เอกสาร → อ่านเป็นฟอร์ม** (§5)
   - ค่าตั้งต้นคืออ่านด้วยเครื่องมืออย่างเดียว
   - ถ้าติ๊ก "ให้ AI ช่วยตรวจและตั้งชื่อ" AI จะได้ภาพทั้งหน้า ภาพขยายจุดที่ไม่แน่ใจ (ไม่เกิน 10 จุด) หลักฐานทุกบรรทัด และแผนของเครื่องมือ แล้วตอบเป็นรายการแก้ที่ระบบตรวจก่อนใช้
   - อ่านแล้วกด "อ่านซ้ำโดยให้ AI ช่วยตรวจ" ได้ โดยไม่ต้องส่งไฟล์ใหม่
2. **ออกแบบฟอร์ม → ✨ AI** มี 3 ขอบเขตให้เลือก
   - **แก้ช่องที่เลือก**: ส่งเฉพาะ id ของช่องที่เลือกเป็น `focus`
   - **แก้ทั้งฟอร์มนี้**
   - **สร้างฟอร์มใหม่จากคำอธิบาย**

   งานจะรันเบื้องหลัง (`POST /api/formdev/ai/jobs`) เมื่อเสร็จ จอจะแสดงรายการช่องที่ถูก **เพิ่ม / ลบ / เปลี่ยน** (`changesOf`) ให้ดูก่อนกดใช้ และย้อนกลับได้ด้วย Ctrl+Z
3. **คลังแม่แบบ → นำเข้าไฟล์ / AI ทั้งเอกสาร** คือการสร้างฟอร์มจากเอกสารทั้งฉบับแบบเดิม (AI-BUILDER.md) สำหรับกรณีที่เครื่องมือแบบที่ 1 อ่านไม่ได้

ทั้งสามจุดใช้การตั้งค่า AI เดียวกัน (Canopy → AI service) และแสดงจำนวน token ที่ใช้ทุกครั้ง

## 3. มาตรฐานชื่อตัวแปร (`app/formdev/ids.py`)

ชื่อตัวแปร (`key`, และ `id` ของช่องใหม่) ใช้ในสูตร เงื่อนไข รายงาน API สาธารณะ และ Flora Leaf ทุกฟอร์มจึงต้องตั้งชื่อด้วยหลักเดียวกัน

1. **snake_case ภาษาอังกฤษตามความหมาย** ยาวไม่เกิน 40 ตัวอักษร
2. **ช่องที่เป็นข้อมูลเคส** (มี concept ใน `concepts.json` เช่น น้ำหนัก ส่วนสูง HN) ใช้ชื่อของ concept เช่น `patient_weight_kg` และจะผูก (bind) กับ concept นั้นให้ด้วย
3. ถ้าไม่ใช่ข้อมูลเคส ระบบจะหาชื่อตามลำดับนี้
   - จาก `label_en` หรือครึ่งภาษาอังกฤษของชื่อสองภาษา ("น้ำหนัก / Weight")
   - ถ้าไม่มีภาษาอังกฤษ ใช้คำแปลใน `TERMS` แล้วตามด้วยการถอดเสียงแบบราชบัณฑิตฯ (PyThaiNLP)
4. **ชื่อกลาง ๆ** (date, time, name, note, result…) จะเติมชื่อส่วนนำหน้า เช่น `consent_date`
5. **ชื่อซ้ำ** จะเติม `_2`, `_3`

ปุ่ม 🔤 ในตัวออกแบบ (`POST /api/formdev/ids/check`) ตรวจหาปัญหา 4 แบบ แต่ละแบบแก้ได้ในคลิกเดียว และมีปุ่ม "แก้ทั้งหมด":

| ปัญหา | ความหมาย |
|---|---|
| `named_by_type` | ตั้งชื่อตามชนิดช่อง เช่น `text_1` แทนที่จะบอกความหมาย |
| `reads_as_case_data` | Flora Leaf จะอ่านช่องนี้เป็นข้อมูลเคสทั้งที่ยังไม่ได้ผูก (มีปุ่ม ⛓ ผูก) |
| `id_differs` | `id` ไม่ตรงกับชื่อตัวแปร |
| `no_english` | ยังไม่มีชื่อภาษาอังกฤษ |

- การเปลี่ยนชื่อช่องที่เผยแพร่แล้ว จะสร้าง migration ให้อัตโนมัติ (`renameTo`)
- ปุ่ม "✨ ตั้งชื่อ" ในแผงขวา (`POST /api/formdev/ids/suggest`) ตั้งชื่อให้ช่องเดียวตามหลักเดียวกัน

## 4. ตัวออกแบบแบบ 2 มิติ (grid 24 คอลัมน์)

ฟอร์มใหม่ใช้ grid 24 คอลัมน์ ซึ่งแบ่งได้ลงตัวทั้งครึ่ง สาม สี่ หก และแปดส่วน ฟอร์มเดิมที่ทำบน 12 คอลัมน์ยังคงใช้ 12 คอลัมน์ตามเดิม

แต่ละช่องมีตำแหน่งและขนาดดังนี้:
- `layout.col` และ `span`: คอลัมน์เริ่มต้นและความกว้าง
- `layout.row` และ `row_span`: แถวและความสูง (สูงได้ถึง 50 แถว)

**การวางช่อง (`core/layout.ts` → `autoPlace`)**
- ใช้หลักเดียวกับ CSS grid (sparse auto-placement) ทั้งจอ PDF และตัวออกแบบ ทั้งสามที่จึงวางช่องตรงกัน
- ช่องที่ไม่ได้ตรึงแถว จะไหลเติมช่องว่างถัดไปตามลำดับการอ่าน

**ลากวาง**
- ลากช่องไปวางที่ **แถวและคอลัมน์ใดก็ได้** โดยมีเงาบอกตำแหน่งระหว่างลาก
- ครั้งแรกที่ลากแบบ 2 มิติ ช่องทั้งรายการจะถูกตรึงตำแหน่งไว้ (`placeAt`)
- ถ้าวางทับช่องอื่น ช่องที่ทับจะถูกดันลงไปแถวถัดไป และลำดับการอ่านยังถูกต้อง

**ย่อขยาย**
- ลากขอบขวาเพื่อปรับความกว้าง ลากขอบล่างเพื่อปรับความสูง หรือลากมุมเพื่อปรับทั้งสองอย่าง
- บนแท็บเล็ตปรับได้เฉพาะความกว้าง

**แป้นพิมพ์**

| ปุ่ม | ทำอะไร |
|---|---|
| ลูกศร | ย้ายช่องทีละคอลัมน์ / แถว |
| Shift + ลูกศร | ย่อขยายช่อง |
| Shift / Ctrl + คลิก | เลือกหลายช่อง แล้วแก้ค่าพร้อมกันในแผงขวา (BulkPanel) |
| Delete | ลบช่องที่เลือก |
| Ctrl+C / Ctrl+V | คัดลอก / วาง (ช่องที่วางได้ชื่อใหม่) |
| Ctrl+D | ทำสำเนา |
| Ctrl+K | ค้นหาส่วนประกอบ (§7) |
| Esc | ยกเลิกการเลือก |
| Ctrl+Z | เลิกทำ |

**แถบบนพื้นที่ออกแบบ**
- เปิด/ปิดเส้น grid
- ย่อขยายหน้าจอ 50–150%
- ปุ่ม "ปิดแถวว่าง" (`compactRows`)

**ส่วนประกอบที่ไม่ใช่ช่องกรอก** (ทั้งสองฝั่ง: `fieldTypes.ts` / `field_types.py`)
- หัวข้อ (`heading`: level, align)
- ย่อหน้า (`paragraph`: content ไม่เกิน 4000 ตัวอักษร)
- เส้นคั่น (`divider`)

**สองภาษา**
- `label` คือชื่อในภาษาของฟอร์ม
- `label_en` คือชื่อภาษาอังกฤษ ส่วน section, category และตัวเลือกมี `title_en` / `label_en` เช่นกัน
- จอและ PDF เลือกภาษาให้ตามภาษาของผู้ใช้ (`core/labels.ts`)
- ปุ่ม "แยกสองภาษา" ในแผงขวาจะตัด "ไทย / English" ออกเป็นสองช่องให้

## 5. อ่านเอกสารเป็นฟอร์มแบบ IDP (`app/formdev/reading/`)

### ทำไมต้องเปลี่ยน (สิ่งที่พบจากเอกสารจริง)

ทดสอบกับเอกสารสแกนจริง ANESTHETIC RECORD ("เอกสาร 16.pdf" ที่เคยใช้สร้างแม่แบบ) ด้วยระบบรุ่นก่อน:

| ขั้น | รุ่นก่อน | ปัญหา |
|---|---|---|
| OCR | อ่านได้ 95 บรรทัด ถูกเกือบทั้งหมด | ไม่ใช่ต้นเหตุ |
| หาโครงสร้าง | มองทั้งหน้าเป็น "ตาราง" เดียว และนับช่องกราฟเวลาเป็น checkbox 1,938 ช่อง | ข้อความเกือบทั้งหมดถูกกลืนหาย |
| ร่างฟอร์ม | ได้ **3 ช่อง** | |
| AI | ได้ดูแค่ภาพตัดของ 3 ช่องนั้น | AI ไม่เคยเห็นส่วนที่เหลือของเอกสาร จึงสร้างได้ไม่ตรง |

สรุป: OCR ไม่ได้ส่งข้อมูลขาด แต่ขั้นแยกโครงสร้างพัง และระบบส่งให้ AI ไม่ครบ จึงออกแบบใหม่เป็นระบบ IDP ตามด้านล่าง

### ขั้นตอน

| ขั้น | โมดูล | ทำอะไร |
|---|---|---|
| 1 | `pdf.py` | ชั้นข้อความของ PDF (ถ้าดีไม่ต้อง OCR), ช่องกรอก AcroForm, ความละเอียดจริงของภาพสแกน (อ่านที่ 200–300 dpi ตามต้นฉบับ ไม่ย่อขยายซ้ำ) |
| 2 | `preprocess.py` | จัดหน้าที่สแกนเอียงให้ตรง (วัดจากเส้นตาราง หรือจากแถวข้อความถ้าไม่มีเส้น; แก้เมื่อเอียง 0.1°–5°) และปรับแสงหน้าที่ถ่ายด้วยกล้องให้สม่ำเสมอ |
| 3 | `ocr.py` + `thai.py` | OCR ไทย/อังกฤษ (RapidOCR, PP-OCRv5 ภาษาไทย บน CPU) และทำข้อความไทยให้ถูก (PUA, สระอำ, วรรณยุกต์) |
| 4 | `layout.py` | **หลักฐานพร้อมรหัส**: บรรทัดข้อความ `L`, เซลล์ที่เส้นตารางปิดล้อม `C`, ตารางกราฟเวลา `G` (ตาราง lattice ช่องเล็ก แยกจาก checkbox), ที่เขียน `B` (เส้นใต้อิสระ, เส้นประ `.....`, `____`), checkbox `K` พร้อมข้อความข้าง ๆ |
| 5 | `understand.py` | **แผนฟอร์มด้วยกฎ** แต่ละรายการชี้กลับไปที่หลักฐาน (ดูตารางกฎถัดไป) |
| 6 | `assemble.py` | (เปิดได้) AI แก้แผนด้วยหลักฐาน ระบบตรวจทุกข้อ + วัดความครบถ้วน (§5 AI) |
| 7 | `draft.py` | แผน → ฟอร์มบน grid 24 คอลัมน์ ตามตำแหน่งบนกระดาษ ตั้งชื่อตามมาตรฐาน §3 ผูก concept และเก็บที่มา (`provenance`: หลักฐาน, ความมั่นใจ, ใครทำ) |

**กฎของขั้นที่ 5** (ลำดับตามนี้ หลักฐานที่ถูกใช้แล้วจะไม่ถูกใช้ซ้ำ)

1. ชื่อเอกสาร: ข้อความใหญ่สุดด้านบนนอกกรอบ (หรือบรรทัดแรกที่ยาวและไม่มีที่เขียนข้าง ๆ)
2. ตารางกราฟเวลา → **timeline**
   - แถว: ชื่อในเซลล์หน้า grid (เช่น URINE, SpO2) ชื่อกลุ่มอย่าง AGENTS จะครอบแถวว่างใต้มันเป็น "AGENTS 1, 2…"
   - กราฟ: เมื่อมีคอลัมน์ตัวเลขแกน (240…20) series มาจาก legend (BP → nibp, PULSE → pr)
   - events: เมื่อมีเครื่องหมาย START/END
   - ถ้าไม่มีแกนหรือเวลา จะเป็นตาราง (repeat)
3. ตารางเส้น: แถวหัวคอลัมน์ (ในเซลล์เดียวหรือเซลล์ละชื่อ) ตามด้วยแถวว่าง ≥2 แถว → **repeat** ชื่อมาจากบรรทัดเหนือตาราง ถ้ามีหัวเดียวเหนือแถวว่าง → textarea
4. ที่เขียน: ป้ายบนเส้นฐานเดียวกันก่อนเส้นใต้/เส้นประ
   - หน่วยหลังเส้นจะกลายเป็น unit (kg, cm, ปี, yr)
   - "ลงชื่อ ……… ผู้บันทึก" เป็นลายเซ็นช่องเดียว
   - เส้นว่างใต้ช่องเดิมทำให้ช่องนั้นเป็นข้อความยาว
5. checkbox: ช่องติ๊กพร้อมข้อความเป็นตัวเลือก ช่องบนแถวเดียวกันเป็น radio/multiselect โดยใช้ป้ายหน้าช่องแรก
6. ตัวเลือกที่พิมพ์ไว้ให้วงกลม: "TUBE : RAE , DLT , MLT" หรือเซลล์ที่มีแต่คำสั้น ๆ และไม่มีที่เขียน
7. ป้ายตามด้วยกรอบว่าง / ป้ายในเซลล์ที่มีที่ว่างทางขวาหรือด้านล่าง / ชื่อบทบาทท้ายหน้า (SURGEON, ผู้บันทึก) → ลายเซ็น
8. ที่เหลือ:
   - สัญลักษณ์ ตัวเลขแกนกราฟ และรหัสฟอร์ม (เช่น น. 6002) ถูกตัดออกพร้อมเหตุผล
   - ข้อความอื่นถูกนับเป็น "ยังไม่ได้ใช้" ให้ AI และผู้ใช้เห็น ไม่มีการทิ้งเงียบ ๆ

### PDF ดิจิทัล (ไฟล์ที่ระบบพิมพ์ออกมา ไม่ใช่สแกน)

PDF ดิจิทัลบอกตำแหน่ง ฟอนต์ และตัวหนาของทุกคำ รวมทั้งเส้นและกล่องทุกเส้นได้ตรง 100% จึงไม่ต้อง OCR และไม่ต้องให้ AI เดา:

| อ่านจาก PDF | ใช้ทำอะไร |
|---|---|
| คำพร้อมตำแหน่ง ขนาด และตัวหนา (`pdf.text_layer`) | ต่อคำเป็นบรรทัดเฉพาะในคอลัมน์เดียวกัน และตัดที่เส้นเซลล์ (เดิมข้อความ 4 คอลัมน์ถูกต่อเป็นบรรทัดเดียว ทำให้ AI สร้างผิด) |
| ตัวหนาตามด้วยตัวปกติ ("**Age:** 64 Y") | สำเนาที่กรอกแล้ว: ส่วนตัวหนาเป็นช่อง ค่าที่กรอกถูกตัดออกเพราะเป็นข้อมูลผู้ป่วย และใช้แค่บอกชนิดและหน่วย (number + yr, decimal + kg, date) |
| checkbox ที่วาดเป็นเส้นเวกเตอร์ (`pdf.checkboxes`) | ได้ตรงทุกช่อง รู้ว่าช่องไหนถูกติ๊ก ช่องเล็กถึง 1.8 มม. ก็อ่านได้ |
| ขนาดฟอนต์ใหญ่สุดด้านบน | ชื่อเอกสาร แม้อยู่ในเซลล์ |
| checklist หลายคอลัมน์ใต้หัว "list \| Qty" | แต่ละหมวดเป็น matrix (รายการ × Qty) ความกว้างคอลัมน์ชื่อตามกระดาษ (`label_width`) แต่ละคอลัมน์ของกระดาษเป็น group ของตัวเอง รายการที่ต่อจากคอลัมน์ก่อนได้ชื่อ "(ต่อ)" แถวว่างสำรองถูกนับไว้ |
| ตัวอักษรเล็ก (< 9 pt) | `paper.density: fit_page` พิมพ์ได้ในจำนวนหน้าเท่าต้นฉบับ |

ตัวอย่างจริง Anesthesia Check List (Billing):
- เดิม: AI สร้างได้ 4 หน้า ข้อความปนกัน checklist หาย
- ใหม่ (ไม่ใช้ AI): 1 หน้า 44 ช่องรวม 15 ตาราง ใช้ข้อความครบ 100% ไม่มี issue

### ให้ฟอร์มหน้าตาเหมือนเอกสาร (`draft.py`)

ตำแหน่งและรูปแบบมาจากการวัดบนกระดาษเสมอ AI แก้ได้แค่เนื้อหา:

| บนกระดาษ | ในฟอร์ม |
|---|---|
| ขนาดกระดาษ แนวตั้ง/แนวนอน และขอบ | `paper.size` (A4/A5/Letter), `orientation`, `margin_mm` วัดจากเนื้อหาจริงของหน้าแรก |
| ตำแหน่งและความกว้างของแต่ละช่อง | grid 24 คอลัมน์: แถวตามบรรทัดป้าย, `col`/`span` ตามตำแหน่ง x |
| กรอบที่สูงกว่าแถวของมัน (DIAGNOSIS, REMARKS) | `row_span` ครอบแถวข้าง ๆ ตราบใดที่ไม่มีช่องอื่นในคอลัมน์เดียวกัน |
| ส่วนที่ตีเส้นเป็นตาราง | `print_style: boxed` (พิมพ์เป็นเซลล์มีเส้นขอบ) |
| ตารางที่มีหัวคอลัมน์และแถวว่างให้เขียน | `repeat` แบบตาราง ความกว้างคอลัมน์ตามเซลล์หัวตาราง (เช่น 12/6/6) ตารางที่วางติดกันแต่จำนวนแถวว่างต่างกันจะแยกเป็นคนละตาราง |
| ตารางที่คอลัมน์แรกพิมพ์ชื่อแถว (ประเมินตามเวร, รายการสารน้ำ) | `matrix` แถว × คอลัมน์ตามกระดาษ หัวคอลัมน์จากแถวบนสุด |
| กราฟเวลา | `timeline` จำนวนคอลัมน์เวลาที่พิมพ์ (`print_columns`) เท่ากระดาษ (8–48) |

**คลังแม่แบบ → AI ทั้งเอกสาร** ทำงานแบบเดียวกัน:
- ถ้ามี PDF หรือภาพสแกน เครื่องมือจะอ่านเป็นร่างที่วัดจากกระดาษก่อน แล้วส่งร่างนั้นให้ AI แก้เนื้อหา
- หลัง AI ตอบ ระบบใส่ตำแหน่ง ขนาด ความกว้างคอลัมน์ กระดาษ และเส้นกรอบกลับคืนให้ทุกช่องที่ AI ยังเก็บไว้ (`keep_paper`)

### AI แบบอิงหลักฐาน (`assemble.py`)

- **สิ่งที่ส่งให้ AI ต่อหน้า**: ภาพทั้งหน้า (1600 px), ภาพขยายจุดที่ไม่แน่ใจหรือยังไม่ได้ใช้ ≤10 จุด, ทุกบรรทัดพร้อมรหัสและตำแหน่ง, เซลล์, ที่เขียน, grid, checkbox, แผนของเครื่องมือ (รหัส I…) พร้อมเหตุผลที่ไม่แน่ใจ
  - AI ไม่ต้องอ่านหน้าใหม่ และไม่ต้องเขียนฟอร์มเองทั้งฉบับ จึงเหมาะกับโมเดลขนาดกลางที่รันบนเซิร์ฟเวอร์ของโรงพยาบาลด้วย
- **คำตอบ**: รายการแก้ ได้แก่ `edit` (ชื่อ, ชนิด, หน่วย, ตัวเลือก, แถว, label_en), `add` (จากหลักฐานที่ยังไม่มีใครใช้), `remove`, `ignore` (พร้อมเหตุผล), ชื่อส่วน และชื่อเอกสาร
- **การตรวจก่อนใช้** (ข้อที่ไม่ผ่านจะถูกปฏิเสธและแสดงบนจอ):

| กฎ | ตัวอย่างที่เจอจริงตอนทดสอบ |
|---|---|
| รหัสที่อ้างต้องมีจริง | — |
| ป้ายต้องอ่านเหมือนข้อความบนหน้า (แก้คำที่ OCR อ่านผิดได้ และจะแสดงเป็น "AI แก้คำ") | `NO/AIR` → `N2O/AIR` ผ่าน |
| ถ้า AI ใส่ความหมายภาษาอังกฤษในช่องป้าย จะย้ายไปเป็น `label_en` และคงป้ายที่พิมพ์ไว้ | `WT` คงไว้ ส่วน "Weight" เป็นป้ายภาษาอังกฤษ |
| ลบช่องที่บนหน้ามีที่เขียน (เส้น/ช่องติ๊ก/กรอบว่าง) ไม่ได้ | Qwen พยายามลบ Hb, Hct, Wbc, Plt ด้วยเหตุผลที่ขัดกันเอง → ถูกปฏิเสธ |
| หน่วยต้องพิมพ์อยู่บนหน้า | g/dL ที่ AI เติมเองถูกปฏิเสธ |
| ชื่อของตัวเลือกห้ามเป็นการท่องตัวเลือก | "TUBE : RAE , Reinforce…" ถูกปฏิเสธ |
| ช่องที่เพิ่มต้องชี้หลักฐาน | — |

- **ความครบถ้วน**: หลังตอบ ถ้ายังมีบรรทัดที่ไม่ได้ใช้ จะถามซ้ำ 1 ครั้งโดยระบุรหัสบรรทัด เซิร์ฟเวอร์ AI ที่ไม่ว่าง (429/502/503/504) จะถูกถามซ้ำ 1 ครั้ง
- **ถ้า AI ใช้ไม่ได้** แผนของเครื่องมือยังคงอยู่ และหน้าจอบอกเหตุผล
  - ตัวอย่าง: Cloudflare 530 / error 1033 คือเซิร์ฟเวอร์ AI หรือ tunnel ล่ม

### ผลกับเอกสารจริงและฟอร์มทดสอบ

| เอกสาร | รุ่นก่อน | IDP เครื่องมืออย่างเดียว | IDP + AI (Qwen 3.6-35B) |
|---|---|---|---|
| ANESTHETIC RECORD (สแกนจริง) | 3 ช่อง | 44 ช่อง, ใช้ข้อความ 97.9%, ผ่าน validator | 100% coverage, แก้ N2O/O2, ตั้งชื่อรายการตัวเลือก/ส่วน/ภาษาอังกฤษ (~22k input tokens, 2 คำขอ, ~90 วินาที) |
| ฟอร์มพยาบาลไทยมีกรอบ เอียง 1.2° (`ruled_form_image`) | — | ใช้ข้อความ 100%, ไม่มี issue, วัดความเอียงได้ 1.18° | — |
| ฟอร์มง่าย (`form_image`) | 6 ช่อง | 6 ช่องเดิม, 100% | — |

สิ่งที่ยังต้องให้ AI หรือผู้ใช้ช่วย:
- OCR ภาษาไทยบางครั้งทำวรรณยุกต์หาย ("ยาทีได้รับ") เมื่อคำที่ได้ยังเป็นคำที่มีอยู่จริง พจนานุกรมจึงแก้ไม่ได้ ต้องให้ AI แก้ (จะแสดงเป็น "AI แก้คำ")
- บรรทัดที่ผสมทั้งช่องกรอกและตัวเลือก เช่น "CUFF__ml., PACK, SIZE"

### การทำงานแบบ job และหน้าจอ

**job (`jobs.py`)**
- รันใน thread pool เอกสารไม่เกิน 40 หน้า เก็บในหน่วยความจำ ≤20 งาน นาน 2 ชั่วโมง
- จอดึงเหตุการณ์ทุก 400 ms (`GET /reading/jobs/{id}?after=n`)
- ชนิดเหตุการณ์: started, form_fields, page, text_layer, prepared, ocr_started, ocr_done, lines, layout, plan, ai_started, ai_done, ai_failed, note, draft, done, failed

**หน้าจอ real-time (`ReadingView.tsx`)**
- บนหน้ากระดาษ:
  - เส้นสแกน
  - ชั้นโครงสร้าง (เซลล์, grid, ที่เขียน, checkbox)
  - บรรทัดที่ระบายสีตามสถานะ: ใช้แล้ว / ตัดออก / ยังไม่ได้ใช้
  - ช่องที่ได้ ระบายสีตาม: แน่ใจ / ไม่แน่ใจ / AI ปรับ / AI แก้คำที่ OCR อ่านผิด
- ชี้ที่ช่อง จะเห็นหลักฐานของช่องนั้นสว่างขึ้นบนหน้า
- แผง AI: สิ่งที่ส่งไป (จำนวนบรรทัด, เซลล์, ภาพขยาย), สิ่งที่แก้, สิ่งที่ถูกปฏิเสธพร้อมเหตุผล, token และเวลา
- แผงความครบถ้วน: บรรทัดที่ยังไม่ได้ใช้ พร้อมปุ่ม "+ เพิ่มเป็นช่อง"

**เครื่องมือที่ใช้**
- ใช้: pypdfium2, pdfplumber, pypdf, RapidOCR + onnxruntime, OpenCV headless, PyThaiNLP (ทั้งหมดรันบน CPU ใช้เชิงพาณิชย์ได้)
- ไม่ต้องติดตั้งอะไรเพิ่มจากชุดเดิม
- ไม่ใช้:
  - PyMuPDF เพราะใบอนุญาต AGPL
  - Surya เพราะหนักและต้องใช้ GPU
  - img2table เพราะดึง opencv-contrib มาด้วย
  - LayoutLM เพราะใบอนุญาตห้ามใช้เชิงพาณิชย์ และต้อง fine-tune
- สำหรับฟอร์มที่มีเส้นตาราง การวิเคราะห์เส้นด้วย OpenCV แม่นกว่าโมเดล layout ทั่วไปที่ฝึกกับเอกสารบทความ

## 6. ประกอบร่างเอกสาร (`src/documents/`)

ทำงานคล้ายการตัดต่อวิดีโอ ทั้งหมดทำในเบราว์เซอร์ และจะไม่อัปโหลดอะไรจนกว่าจะกดใช้กลุ่มเอกสาร

1. **เพิ่มเอกสาร**: ลากไฟล์ PDF หรือรูปสแกน (PNG/JPEG) มาวาง
   - แต่ละหน้าถูกแยกออกเป็น "คลิป" มีภาพย่อ (pdf.js) และไปรอใน **ถาด**
2. **จัดกลุ่ม** (กลุ่ม = เอกสาร 1 ฉบับ)
   - ลากหน้าเข้ากลุ่ม หรือเรียงลำดับใหม่
   - เลือกหลายหน้าด้วยคลิก / Shift / Ctrl
   - หมุนหน้า (R) ลบหน้า (Delete)
   - "ตัดตรงนี้" แยกเป็นเอกสารใหม่, "ต่อกลุ่มถัดไป", "ยกเลิกกลุ่ม"
   - "จัดกลุ่มตามไฟล์" ในคลิกเดียว
   - เปิดดูทีละหน้าแบบขยายได้
3. **ใช้กลุ่มเอกสาร** (`mergeClips` รวมเป็น PDF ฉบับเดียวด้วย pdf-lib)
   - หน้าที่มาจาก PDF ถูกคัดลอกตามเดิม ทั้งเวกเตอร์และชั้นข้อความ และบวกมุมหมุนที่เลือกไว้
   - รูปถูกวางบน A4 ตามแนวของรูป (แนวตั้งหรือแนวนอน) โดยเว้นขอบ 8 มม.

   ใช้ได้ 3 ทาง ตามที่เลือกไว้:
   - **ต้นแบบสร้างฟอร์ม**: อ่านเป็นฟอร์มตาม §5
   - **ดาวน์โหลด PDF รวม**
   - **แนบเข้าเคสบน Leaf**: ดูหัวข้อถัดไป

### แนบเอกสารเข้าเคส (Leaf → Canopy, migration 0092)

- **ฝั่ง Leaf: Reports → เอกสารแนบของเคส** (`CaseDocumentsPanel`)
  - ประกอบร่างแล้วแนบ PDF เข้าเคส ขนาดไม่เกิน 30 MB และต้องเป็น PDF เท่านั้น
  - แนบเข้าเคสที่ archive แล้วไม่ได้
  - การลบไม่ลบจริง แต่บันทึกผู้ลบและเหตุผล (อย่างน้อย 3 ตัวอักษร)
  - การแนบและการลบถูกบันทึกใน `case_clinical_audit`
- **ชุดเอกสารเคส (case packet)** จะรวมเอกสารแนบที่ยังไม่ถูกลบไว้ด้วย
- **sync worker** (`synchronize_case_documents`)
  - ส่ง **รายละเอียด** ของเอกสาร (JSON เล็ก ๆ ไม่มีตัวไฟล์) ก่อน Canopy ตอบว่ายังต้องการไฟล์หรือไม่ (`needs_content`)
  - ส่ง **ตัวไฟล์ PDF ตามจริง** (ไม่ใช้ Base64) เฉพาะเมื่อ Canopy ยังไม่มี Canopy ตรวจ SHA256 ถ้าไม่ตรงจะปฏิเสธ
  - เมื่อถูกลบ ส่งเฉพาะรายละเอียด ไม่ส่งไฟล์ซ้ำ
  - เก็บไว้ที่ `canopy_case_document` ตาม global case id ระหว่างที่ไฟล์ยังมาไม่ถึง จอ Canopy แสดง ⏳
- **ฝั่ง Canopy: เคส → แท็บฟอร์ม → เอกสารแนบจาก Leaf** (`CaseDocumentsReview`) เปิดดูได้

## 7. ค้นหาส่วนประกอบ (Ctrl+K, `designer/Finder.tsx`)

ช่องค้นหาเดียวค้นได้ทุกอย่างที่ใช้ประกอบฟอร์ม ทั้งภาษาไทยและอังกฤษ และไม่สนลำดับคำ:

- ชนิดช่อง
- ชุดสำเร็จรูป
- **ข้อมูลเคส (concept)**: ช่องที่ได้มาจะผูก concept และตั้งชื่อตามมาตรฐานมาให้แล้ว
- **ชุดของทีม**: บันทึกจากช่องที่เลือก ด้วยคำสั่ง "บันทึกเป็นชุดของทีม" ระบบเก็บเป็นแม่แบบ `block_<ชื่อ>`
- **ส่วนจากแบบฟอร์มอื่น**: ฉบับที่เผยแพร่ล่าสุดของฟอร์มนั้น
- ช่องในฟอร์มนี้ (กระโดดไปที่ช่อง)
- คำสั่งของตัวออกแบบ

แถบซ้าย (palette) ก็มีช่องค้นหาเช่นกัน

## 7.1 ส่วนประกอบรายงาน: ตารางข้อมูลเคส (`case_block`)

ใช้ทำรายงาน เช่น Billing หรือ PACU ที่ต้องพิมพ์ข้อมูลจริงของเคสจาก Flora Leaf ลงกระดาษ A4 ตามแบบที่วาดไว้
แต่ละตารางเป็นฟิลด์หนึ่งช่องในฟอร์ม ไม่มีคนกรอก และไม่เก็บค่าลงในบันทึก

| ส่วน | ไฟล์ |
|---|---|
| แคตตาล็อกบล็อก: 11 ชนิด, คอลัมน์, ความกว้างเริ่มต้น | `formdev/spec/case-blocks.json` (คู่: `core/caseBlocks.ts`, `app/formdev/case_blocks.py`) |
| ตรวจสอบนิยามฟอร์ม | `validate.ts` `validateCaseBlock` / `definition.py` `_validate_case_block` |
| ดึงข้อมูลจากเคสตอนพิมพ์ (อ่านอย่างเดียว) | `leaf/caseBlocks.ts` `fillCaseBlocks`, `blockRows` |
| PDF / หน้าจอ / canvas | `pdfLayout.ts` `caseBlockTable`, `ui/CaseBlockTable.tsx` |
| แผงตั้งค่า | `designer/CaseBlockEditor.tsx` |

**บล็อกที่มี:** diagnoses, procedures, allergies, labs, events, staff, medications, fluids, outputs, billing, scores
(สัญญาณชีพตามเวลายังใช้ `timeline` เหมือนเดิม)

**ค่าที่ตั้งได้ในฟิลด์**
- `block`: ข้อมูลที่จะแสดง
- `block_columns`: `[{key, width?, label?}]` คอลัมน์ตามลำดับบนกระดาษ
  - `width` คือ % ของความกว้างตาราง รวมกันต้องไม่เกิน 100
  - คอลัมน์ที่ไม่ใส่ width จะแบ่งส่วนที่เหลือกัน
  - ถ้ารวมแล้วไม่ถึง 100 ตอนพิมพ์จะขยายตามสัดส่วนให้เต็ม
- `max_rows`: แถวสูงสุดที่พิมพ์ (ค่าเริ่มต้น 20) ถ้ามีมากกว่านี้ จะแจ้งจำนวนที่ไม่ได้พิมพ์ไว้ใต้ตาราง
- `min_rows`: แถวว่างที่มีเส้นตาราง สำหรับเขียนด้วยมือ
- `show_header`: พิมพ์หัวคอลัมน์หรือไม่

**ใน Form Studio**
- แถบเครื่องมือมีกลุ่ม "ส่วนประกอบรายงาน (ข้อมูลเคส)" ลากหรือคลิกได้ 1 ปุ่มต่อ 1 บล็อก ค้นหาด้วย Ctrl+K ก็ได้
- แผงขวามีส่วน "ตารางข้อมูลเคส" ใช้ทำสิ่งต่อไปนี้:
  - เลือกบล็อก
  - เปิด/ปิดคอลัมน์และเรียงลำดับ
  - ตั้งความกว้างเป็น % ได้ทั้งแถบเลื่อนและช่องตัวเลข มีแถบสีแสดงสัดส่วนและยอดรวม
  - ปุ่ม "ปรับให้รวม 100%" / "แบ่งเท่ากัน" / "ค่าเริ่มต้น"
  - แก้หัวคอลัมน์ที่จะพิมพ์ และตั้งจำนวนแถว
- ส่วน "ขนาดและตำแหน่ง" ใช้ได้กับทุกฟิลด์:
  - แสดงความกว้างเป็นจำนวนช่องบน grid, % และประมาณ mm บนกระดาษ
  - มีแถบเลื่อนความกว้าง และช่องตั้งความสูง (`row_span`)
- แท็บพิมพ์แสดงตารางเป็นข้อมูลตัวอย่าง
  - มีป้าย 📄 บอกว่า "พอดี A4 1 หน้า" หรือ "N หน้า" และ % ที่ย่อ
  - ปุ่ม "บีบให้พอดี 1 หน้า" จะตั้ง `paper.density: fit_page`

**ใน Flora Leaf (Reports → Form Studio)**
- ดึงเฉพาะแหล่งข้อมูลที่บล็อกในฟอร์มนั้นต้องใช้
- ตาราง "ดูว่าแต่ละช่องมาจากไหน" แสดงจำนวนแถวของแต่ละบล็อก
- มีป้ายบอกจำนวนหน้า A4 แบบเดียวกับใน Form Studio

**AI รู้จักบล็อกเหล่านี้**
- `ai_builder.SYSTEM_PROMPT` มีรายการบล็อกพร้อมคอลัมน์ และกติกา "ONE PAGE"
- ขั้นอ่านเอกสาร (`assemble.py`) แก้ตารางเป็น `case_block` ได้ แต่ต้องเป็นบล็อกที่มีอยู่จริง ไม่อย่างนั้นจะคงไว้เป็นตาราง
- `draft.py` ตั้งความกว้างคอลัมน์ตามที่วัดได้จากกระดาษ และใช้จำนวนแถวว่างบนกระดาษเป็น `min_rows`

## 8. ติดตั้ง ขนาด และการส่งไฟล์

**การส่งไฟล์ (ไม่ใช้ Base64)**
- ปัญหาเดิม:
  - Base64 ทำให้ไฟล์ใหญ่ขึ้น 1/3
  - เซิร์ฟเวอร์ต้องถือไฟล์ไว้ราว 3 ชุดพร้อมกัน (ข้อความ JSON, สตริง และไบต์)
  - เบราว์เซอร์ต้องแปลงไฟล์ใหญ่เป็นสตริง
  - AI builder ยังส่งไฟล์ 2 รอบ (ตอนตรวจและตอนสร้าง) และเรนเดอร์ทุกหน้าเป็น PNG แล้วแปลง Base64 ซ้ำอีก
- ตอนนี้:
  - `POST /api/formdev/uploads?name=`: ตัว body คือไฟล์ อ่านทีละส่วนลงดิสก์ ปฏิเสธทันทีเมื่อเกิน 30 MB และตรวจไฟล์ตอนรับ (`app/request_body.py`, `app/formdev/uploads.py`)
  - เก็บตาม SHA-256 แยกตามผู้ใช้ 2 ชั่วโมง (ไฟล์เดียวกันเก็บครั้งเดียว ผู้ใช้อื่นมองไม่เห็น)
  - การอ่านเอกสารและการสร้างด้วย AI อ้างไฟล์ด้วยรหัส (`{upload}` / `{uploads: [...]}`) อ่านซ้ำได้โดยไม่ต้องส่งใหม่
  - หน้า PDF สำหรับเซิร์ฟเวอร์ AI แบบ OpenAI ถูกเรนเดอร์ที่เซิร์ฟเวอร์ด้วย pypdfium2
  - `/ai/inspect` เลิกใช้แล้ว เพราะตรวจตอนอัปโหลด
  - เอกสารแนบเคสใช้ตัว body เป็น PDF และ worker ส่งไฟล์เฉพาะเมื่อจำเป็น (§6)
- nginx ฝั่ง edge ของ Canopy/Leaf รับ body ได้ 50 MB อยู่แล้ว

**โมเดล AI ที่ทดสอบ** (ผ่าน `ai.esm-solution.com`)
- `qwen3/qwen3.6-35b` อ่านภาพได้และทำตามรูปแบบคำตอบได้ดี
- `gemma/gemma-4-31b` ตอบ error 400 เมื่อส่งภาพไปบนเซิร์ฟเวอร์นี้
- `nemotron-3-omni-30b` ใช้ token หมดก่อนตอบ
- บนเซิร์ฟเวอร์มีรุ่น Claude ให้เลือกด้วย หากต้องการคุณภาพสูงกว่า


- **ไลบรารี**: อยู่ใน `services/flora-api/requirements.txt` ทุกตัวระบุเวอร์ชันแน่นอน
- **โมเดล OCR**: `scripts/fetch_ocr_models.py` ดาวน์โหลดตอน build image จาก URL ที่กำหนดไว้แน่นอน และตรวจ SHA256 แล้วเก็บไว้ที่ `/opt/flora-ocr` (`FLORA_OCR_MODELS`)
  - ตอนใช้งานจริงไม่ดาวน์โหลดอะไรเลย
  - ถ้าไม่มีโมเดล การอ่านเอกสารยังทำงานได้กับ PDF ที่มีชั้นข้อความ แต่จะไม่ OCR
  - `GET /api/formdev/reading/status` บอกว่ามี OCR และ AI หรือไม่
- **ข้อมูล PyThaiNLP**: เก็บที่ `PYTHAINLP_DATA=/tmp/pythainlp-data` ใช้แบบออฟไลน์
- **ขนาด image**: image ของ API (leaf-api, sync-api, canopy-api ใช้ Dockerfile เดียวกัน) เพิ่มเป็นประมาณ 1.0 GB
- **CI**: job `test-api` ติดตั้ง `fonts-noto-core` และดาวน์โหลดโมเดลแบบเดียวกับตอน build image ทำให้เทสต์การอ่านเอกสารรันจริง ไม่ถูกข้าม ส่วน `test-db` รวมเทสต์เอกสารแนบเคสไว้แล้ว
